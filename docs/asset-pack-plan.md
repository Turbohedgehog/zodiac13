# План: архив ресурсов

## Контекст

Ресурсы игры (`assets/`, `config/`) лежат каталогами рядом с исполняемым файлом, и код открывает их по путям `std::filesystem` — каждый читатель свой путь: лаунчер, палитра и чертежи (`building_module/src/asset_file.cpp`), рендер (`raylib_module/src/tools/asset_path.cpp`), шейдеры, модели через assimp. Пакеты релиза (zip Windows, tgz и deb Linux) несут тысячи мелких файлов, а на Android APK не даёт `std::filesystem` заглянуть внутрь — ресурсы распаковываются во внутреннее хранилище при первом запуске (`src/zodiac13/android_main.cpp`) и лежат на телефоне дважды.

Цель (просьба от 2026-10-14): сборка упаковывает ресурсы в один архив, игра на всех платформах читает их из него; каталог остаётся для разработки.

## Проектные решения

- **Источник ресурсов** в `lib_core`: открыть файл по относительному пути (`station/palette.json`, `shaders/lighting.fs`) — байты или поток, ошибка через `std::expected`. Два источника: каталог и архив. Какой — решает лаунчер (сборка для разработки читает каталог, чтобы ресурс правился без пересборки; пакет релиза и APK — архив); остальной код не знает.
- **Все читатели — через источник**: палитра и чертежи (`primitives`), шейдеры, текстуры и скайбокс (`LoadImageFromMemory`), модели (assimp — через свой `IOSystem`), конфиги по умолчанию. Пути `std::filesystem` к ресурсам уходят из кода; `InstallDir()` остаётся только для плагинов и данных пользователя.
- **Формат — zip**: уже сжатые файлы (jpg, dds, glb, fbx) без сжатия, остальное со сжатием; читатель zip — из vcpkg (assimp уже тянет `kubazip`/`minizip`). Архив пересобирается, только когда меняются ресурсы.
- **Android**: архив лежит в APK несжатым (`noCompress`) и читается через `SDL_IOFromFile` (AAssetManager) прямо из APK — без распаковки и без второй копии; `android_main.cpp` больше не распаковывает.
- **Тесты** пользуются тем же источником: каталог `assets/` из дерева исходников (`z13_tests/shipped_station.h`), архив — в тестах самого архива.

## Порядок работ (одна ветка на этап)

1. **`f/asset-source`** (~500): источник ресурсов с каталогом, все читатели через него, `AssetFile`/`AssetPath` уходят. Поведение не меняется. Тесты: отсутствующий файл — ошибка, а не пустой ресурс; палитра, чертёж и шейдер читаются через источник.
   Сделано (`f/asset-source`). Отличия: `AssetSource` (`lib_core/utils/asset_source.h`) читает `assets/` и `config/` и перечисляет каталог (список сцен); лаунчер отдаёт его в `Core::SetAssetSource`, а `Core::CreateWorld` ставит синглтон `Assets` до модулей — палитра грузится уже при создании мира. Тесты берут ресурсы из дерева исходников (`z13::testing::SourceAssets()`). Модели assimp читает из памяти (`ReadFileFromMemory`), а не через свой `IOSystem`: у моделей станции и корабля всё, кроме текстур, в одном файле, а текстуры ищутся через источник; `IOSystem` понадобится с первой моделью из нескольких файлов (gltf с `.bin`). `InstallDir()` остаётся корнем источника и каталогом плагинов. Распаковка на Android — до этапа 2.
2. **`f/asset-pack`** (~500, после 1): упаковка при сборке, источник-архив, пакеты релиза и APK несут архив; на Android — чтение из APK без распаковки. Тесты: каталог и архив дают одинаковые байты; CI проверяет, что в архиве каждый файл `assets/` и `config/`.

## Открытые вопросы

- Один архив или по одному на набор (станция, модели, текстуры) — чтобы обновление меняло меньше; решить по размерам на этапе 2.
- Читатель zip: `kubazip`, `minizip` или `libzip` — по тому, что уже есть в дереве и умеет читать из памяти/потока (Android).
