# Codebase map

The per-module description that CLAUDE.md summarises in one line each, moved here verbatim (2026-11-18, the "`CLAUDE.md` велик" debt in `client-server-plan.md`). Keep it current when a module is added, moved or split.

- `src/lib_profile` — `z13_profile`, header-only: `Z13_PROFILE_ZONE`/`Z13_PROFILE_FRAME` (`lib_profile/profile.h`), Tracy zones compiled in only with `Z13_PROFILE`; usage in the perf-measure skill.
- `src/lib_core` — flecs/module plumbing used by every module (a shared library, `z13_core`), headers under `include/lib_core/<group>/`, sources mirrored in `src/<group>/`: `commands/` (`command.h`: a command is a request component with a nested `Command` alias, `Tags` that channels filter by, and `CommandSystem` handlers filling `ReplyOf<T>`; `command_registry.h`: `Commands`, `SubmitCommand` with the arguments and the reply as `rfl::Generic`, so no channel's text format is in the core; registered through `RegisterComponent`), `world/` (`core.h`/`core_types.h` flecs world setup, `lifecycle.h` world-creation stages, `phase_order.h`, `module_factory_base.h` plugin factory interface), `time/` (simulation clock, tick pacer, `tick_log.h` the tick in log lines), `state/` (state markers, snapshots and their codec, rollback, save/load), `settings/` (`config.h`, core settings), `utils/` (`log.h`, `frame_timeline.h`/`frame_recorder.h`/`frame_report.h` (the frame report of the last seconds, docs/frame-time-plan.md), `text_lines.h`, `statistics.h`, `math.h`, `pose_smoothing.h`, `drawn_poses.h`, `flecs_utils.h`, `endpoint.h`, `asset_source.h` (the game's files, the `Assets` singleton: a directory, or the `z13.pack` archive of `asset_pack.h` that `tools/pack_assets.py` writes and a package and the APK carry), `thread_pool.h` (the process's `ThreadPool` singleton, over Taskflow)).
- `src/lib_z13/components/include/z13/components` — flecs component structs shared across modules (`building.h`, `gameplay.h` (game flags; `gameplay_phases.h`, `player.h`, `player_parts.h` beside it), `bootstrap.h`, `status.h`, `z13.h`; station split by topic: `block.h`, `block_brush.h`, `station_mode.h`, `spawn_point.h`, `interaction.h` (a tick's `Interactions`, `InteractionPhase`), `switch.h`; input split by topic: `action_id.h`, `action_map.h`, `action_listener.h`, `input_config.h`, `input_events.h`, `input_phases.h`, `input_state.h`) and `constants/constants.h`.
- `src/lib_z13/modules/z13_module` — main gameplay module: `bootstrap/`, `gameplay/`, `input/` (`gameplay_input_system`). Factory in `z13_module_factory.cpp`. Its own tests live under `tests/`, with the `Z13TestWorld` harness in `tests/support/z13_test_world.h`.
- `src/lib_z13/modules/bullet_module` — Bullet physics plugin. `bullet_components.h` exposes only `RigidBody` (component used outside the module); `PhysicsWorld` (the Bullet collision-world singleton: the blocks are static collision objects, nothing is stepped) is declared in `physics_world.h`/`physics_world.cpp`, private to the module. Factory in `bullet_module_factory.cpp`.
- `src/lib_z13/modules/building_module` — building plugin, loaded right after `z13_module`: the ship scene's building tool, the block palette (`BlockPalette`), and in station mode (`StationMode`, `z13/components/station/station_mode.h`) filling a new scene from a blueprint (`assets/station/blueprints/`), the brush (`BlockBrush`) and building/destroying grid blocks (`Block` in `block.h`) through `BlockIndex` and `ValidateBuild`. Systems in detail: plan-and-debt skill, references/modules.md. Factory in `building_module_factory.cpp`.
- `src/lib_z13/modules/station_module` — station core plugin (`docs/station-systems-plan.md`): `RoomSystem` keeps a `RoomCache` (rooms and portals, derived from the blocks by `rooms`) and a `TopologyVersion` (state) on each grid's entity, `RoomOverlaySystem` fills `RoomOverlay` (F4); `InteractionSystem` finds each tick's interactions (use, hold, presence; docs/station-systems-plan.md, "Взаимодействие"), `SwitchSystem` is their first consumer. Factory in `station_module_factory.cpp`.
- `src/lib_z13/modules/door_module` — door plugin, loaded right after `station_module` (docs/station-systems-plan.md, "Двери"): `DoorSystem` gives door blocks their `DoorState` and moves them (powered, by hand, held shut by a `DoorInterlock`), and keeps `DoorPortals`. Factory in `door_module_factory.cpp`.
- `src/lib_z13/modules/lift_module` — lift plugin, loaded right after `door_module` (docs/station-systems-plan.md, "Лифт"): a `Lift` (`z13/components/station/lift.h`) on the entity that holds the cabin's `KinematicBody` (a solid moving by a formula of the tick, carrying a grounded player: `bullet_module`, docs/dynamic-objects-plan.md); `LiftSystem` sends an idle cabin to its other stop when a player uses the Switch block at either button's cell. Factory in `lift_module_factory.cpp`.
- `src/lib_z13/modules/conduit_module` — conduit plugin (docs/station-systems-plan.md, "Проводка"): `Conduit` runs of cables, wires and pipes (`z13/components/station/conduit.h`, kinds in `assets/station/conduits.json`) sharing cells with blocks, and the conduit tool that lays and removes them (`ConduitToolSystem`, with a `ConduitIndex` of the tick), and `NetworkSystem` (`UtilityNetworksPhase`) keeping the `StationNetworks` singleton (`networks`) of the runs and the blocks' ports. Factory in `conduit_module_factory.cpp`.
- `src/lib_z13/modules/power_module` — power plugin, loaded after `conduit_module` (docs/station-systems-plan.md, "Электричество"): `PowerSystem` balances each power network of `StationNetworks` every `PowerTuning::step_ticks` ticks (and when the networks change) and writes `UtilityDemand`/`UtilitySupply` on consumers and `BatteryCharge` (state) on batteries; `PowerOverlaySystem` fills the `power` layer of `OverlayLayers` (F6), `LampSystem` lists the lamps the networks cannot supply as `DimmedLamps` once the station has had power (`LampsFollowPower`, latched), which `primitives::LightsOf` turns into red emergency light at `power.emergency_light_percent`. Its blocks are the palette fragment `assets/station/palette/power.json`. Factory in `power_module_factory.cpp`.
- `src/lib_z13/modules/atmos_module` — atmosphere plugin, loaded after `power_module` (docs/station-systems-plan.md, "Газ и тепло"): `AtmosSystem` keeps `RoomAir` (state, on the main grid's entity: each room's gases and heat by its anchor, carried over a graph switch by the cells the old and new rooms share, `CarryAir`), and every `AtmosTuning::step_ticks` ticks lets the air flow through the portals (doors by how far open), breathes it for the players, holds the rooms of powered units' vents at their targets, and sets `DoorInterlock` on doors between very different pressures (`DoorSystem` ignores a body in their sensor); `AtmosOverlaySystem` fills the `pressure` layer (F6). Its blocks are the palette fragment `assets/station/palette/atmos.json` (`AtmosUnit`, `Vent`). Factory in `atmos_module_factory.cpp`.
- `src/lib_z13/modules/gravity_module` — gravity plugin, loaded after `atmos_module` (docs/station-systems-plan.md, "Гравитация"): `GeneratorSystem` raises the `GravityCharge` (state) of each powered generator block (`assets/station/palette/gravity.json`) over `physics.generator_ramp_ticks` ticks, lowers it without power, and publishes them as `GravitySources`; `GravitySystem` (`RoomGravity`) turns the sources into each room's pull (the strongest generator within `physics.generator_radius_cells` of the room's box; without generators every room pulls). Factory in `gravity_module_factory.cpp`.
- `src/lib_z13/modules/door_render_module` — door render plugin, loaded after `raylib_module` (client only): `DoorLeafSystem` gives each door the `SceneMesh` of its leaf, rolled up into the opening by `DoorState::position`, as `raylib_module`'s chunk meshes leave the leaves out (`DoorLeaves::kApart`). Factory in `door_render_module_factory.cpp`.
- `src/lib_z13/modules/conduit_render_module` — conduit render plugin, loaded after `raylib_module` (client only): `ConduitMeshSystem` gives each `Conduit` the `SceneMesh` (`z13/components/gameplay/scene_mesh.h`, the render API) that `raylib_module`'s `SceneMeshSystem`/`SceneMeshes` uploads and draws lit; a box per run, no shadows. Factory in `conduit_render_module_factory.cpp`.
- `src/lib_z13/modules/mcp_module` — debug channel plugin (`docs/debug-server-plan.md`): a loopback TCP server (Boost.Asio, its own thread, one JSON request per line) that hands requests to the commands (`SubmitCommand`, filtered by the tags of the `McpServer` setting, on by default, switched in the main menu); `McpServerSystem::Pump` runs in `PreFrame` and the command phases are presentation phases, so it answers in the menu and on pause; `server_status` and `subscribe` are answered by the server's own thread, and a subscribed client is sent what the player says in the console's Assistant tab (`AssistantChat`, `z13/components/console/`; `tools/mcp/console_listen.py` follows it). Factory in `mcp_module_factory.cpp`.
- `src/lib_z13/modules/station_editor_module` — station editor plugin (`docs/station-editor-plan.md`), loaded last: the `EditorGraph` singleton (a `GraphEditor` over the graph being edited, not state: its source is a file) and the `editor`-tagged commands (`editor_load`, `editor_show`, `editor_save`, `editor_set_room`/`remove_room`, `editor_add_edge`/`remove_edge`, `editor_set_property`, `editor_undo`/`redo`, `editor_diagnose`) that the console and the debug channel share. Factory in `station_editor_module_factory.cpp`.
- `src/lib_z13/primitives` — `primitives`, a stateless static library: parses/validates the block palette (`assets/station/palette.json`, schema `primitives.fbs`) into plain types (`BlockPalette` singleton, loaded by `building_module`) and blueprints (`blueprint.fbs`, blocks naming palette primitives) and the lights of lamp blocks (`lights.h`), and builds each primitive shape as convex solids in cell units, from which both the mesh and the collision hull come, and places it on the grid (`placement.h`: 24 orientations, occupied cells, pose); a primitive's `ports` join utility networks, and utility modules add primitives as palette fragments (`assets/station/palette/<module>.json`, declared through `UtilityModules`).
- `src/lib_z13/rooms` — `rooms`, a stateless static library without flecs: `BuildRooms` splits the free space into rooms (column intervals, flood fill) and finds the portals of doors and windows; `RoomCache` (graphs by block fingerprint), `OverlapsBetween` (what a rebuild did to each room), `ViewCulling` (the camera's frustum and the rooms seen through portals), `BoxTree` (a bounding volume hierarchy over boxes, refit when they move, that `StationProps` asks for the props in view) and the routes the measuring benches walk (`TourViewpoints`, `CorridorWalk`, `SpaceWalkRoute`); independent work runs through a `ParallelFor` (`RoomSystem` hands in its `ThreadPool`).
- `src/lib_z13/networks` — `networks`, a stateless static library without flecs: `BuildNetworks` joins the conduit runs of one network that share a face, and the ports (a block's cells) that touch them, into `Network`s whose order depends on cells only; the world side and the components (`z13/components/utility/utilities.h`: `UtilityDemand`, `UtilitySupply`, `UtilityProvider`, the `UtilitySimulationPhase`/`UtilityConsumersPhase` anchors `station_module` registers) are the contract network modules share.
- `src/lib_z13/station_graph` — `station_graph`, a stateless static library without flecs: the station graph of the editor (`Graph`: rooms as boxes in cells and the edges between them, with properties), its property schema (`assets/station/graph/properties.json`: `PropertySchema`, `ParsePropertyValue`), the file (`ParseGraph`/`WriteGraph`), `GraphEditor` (edits that are refused with a reason or kept, undo and redo) and `Diagnose`; `docs/station-layout/station_graph.py` turns a graph into a blueprint.
- `src/lib_z13/power` — `power`, a stateless static library without flecs: `Solve` balances one network's producers, consumers and batteries in whole watts and watt-ticks (priority, then the caller's order, no skipping), and `port_names.h` names the power ports' roles, values and priorities.
- `src/lib_z13/atmos` — `atmos`, a stateless static library without flecs: `Air` in whole millimoles and millijoules (diatomic ideal gas: pressure 2/5 of the energy over the volume), `Exchange` (flow through openings between chambers and the vacuum, from a start snapshot, so the sum is kept), `Breathe` and `Regulate` (a body, a unit), `port_names.h` for the gas ports.
- `src/lib_z13/cell_light` — `cell_light`, a stateless static library without flecs: `CellLight` floods the static lamps' light through the free cells, kept per node (the free piece of a meter cube) and updated where blocks or lamps change. Glass lets through its `light_transmission` share, over bridges between the nodes on its two sides.
- `src/lib_z13/grid` — `grid`, a stateless static library without flecs: `BlockIndex` (which block occupies which cells, filed by chunk; ray along the grid), kept by `building_module` as a component of each grid's entity (`z13/components/station/grid.h`: `Grid`, `MainGridData<T>` for readers of the main grid's).
- `src/lib_z13/sectors` — `sectors`, a stateless static library without flecs: `SectorOf`/`SectorsTouched` (a sector is a cube of `net.sector_size_cells` cells, a multiple of the index chunk) and `SectorIndex` (the sector a player is in, every sector a block touches), kept as a singleton by `net_module`'s `SectorSystem` (`docs/network-scaling-plan.md`).
- `src/lib_z13/input` — `input`, a stateless static library: `LoadInputConfig` and the action negotiation (`input/input_config_loader.h`, `input/action_negotiation.h`) that `z13_module`, `building_module`, `conduit_module`, `station_module` and `net_module` share, so no plugin includes another's headers.
- `src/lib_z13/player` — `player`, a stateless static library: `SpawnPlayer` (`player/gameplay_entities.h`) the look and movement of the free camera (`player/camera_look.h`) and the crew's posts (`player/roles.h`: `roles.json`, `AssignRole`/`GiveRole`, what the server gives a joiner by the posts asked for), shared by `z13_module`, `building_module` and `net_module`.
- `src/lib_z13/outline` — `outline`, a stateless static library without flecs: the outlines of the rooms the overlay (F4) draws (`RoomBoxCache`, `WallOutline`, `RoomBoundary`, `OutlineEdges`), moved out of `station_module` so a Debug build compiles them with `-O1`.
- `src/lib_z13/console_input` — `console_input`, a stateless static library: a console line to the arguments of a command (`SplitCommandLine`, `ArgumentsOf` by each field's kind, `SubmitCommandLine`) and a reply as text, and `RunConsoleLine`, what the console does with a typed line, including a setting's path as a variable (`RunVariable`: the path alone shows its value, with a value changes it), and what Tab and typing offer (`CompletionOf`: commands and paths; `StepLineCompletion`: the selected rest or the list, without ImGui, so `FieldSim` in the tests can play a field) (the commands `help`, `clear`, `quit`, `exit`, `echo` and `console_say` are `z13_module`'s `console/`; the log it shows is `lib_core`'s `ConsoleLog`, filled by a spdlog sink the launcher adds).
- `src/lib_z13/touch` — `touch`, a stateless static library without flecs: maps touches to input (`touch_mapping.h`: the floating stick with its dead zone and steps, the look zone, the buttons laid out by the `TouchLayout` settings), for `z13_module`'s `TouchInputSystem` and the raylib HUD.
- `src/lib_raylib_module` — rendering/platform/GUI plugin: `render/` (environment, the lamps' baked light (`cell_light` on 3D textures), flashlights (Forward+ clusters) and shadow maps, skybox, render resources; remote entities are drawn through `pose_smoothing`), `platform/` (SDL), `gui/` (ImGui windows/keybindings, the console drawn over every screen on the backquote key or a touch button (`console_window`, docs/console-plan.md), the interface font `assets/fonts/`), `tools/` (asset loading, Assimp, input publishing, math conversion). Factory in `raylib_module_factory.cpp`.
- `src/lib_z13/z13_launcher` — loads module factories (`.so` plugins) into one flecs world at startup.
- `src/lib_z13/schemas/fbs` — FlatBuffers schemas more than one library uses (`z13_generate_schemas`, `cmake/z13_schemas.cmake`); a schema with one user lives beside it (`net_module/fbs`, `primitives/fbs`, `building_module/fbs`).
- `src/tests` — the `z13_test_runner` gtest binary; links module factories directly (see `Z13TestWorld`) rather than loading them as plugins.
- `src/zodiac13` — the actual game executable (`main.cpp`).
